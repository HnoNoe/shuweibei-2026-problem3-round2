# b = 0.2 弱占优：解析论证（第 5 步）

> 结论先行：对任意作业、任意时刻、五种映射下，取最小预留 b = 0.2 不劣于任何更大预留，
> 且每单严格省下 0.1×(b₂ − 0.2) 的费用。**b 不需要优化，直接钉死 0.2。**

## 1. 模型事实（全部来自仿真器 `round2/src/simulator.py` 与 `common.py`）

执行作业 j 时：

```
s = t + D + 0.5          # 服务开始 = 当前时刻 + 移动距离 D + 换型 0.5
p = α·d + β              # 作业时长（映射参数 α, β；d 为真实时长）
C = s + p                # 完成时刻
overrun = max(min(p, H−s) − b, 0)   # 超时部分
设备下次可用 = s + max(p, b)         # execute 返回后 t 的取值
费用 = 2.0 + 0.1·b + 0.2·D           # b 只出现在预留费一项
```

## 2. 五步推导

**第 1 步：完成时刻 C 与 b 无关。**
C = s + p，右端没有任何一项含 b。改变 b 不改变完成时刻、不改变是否准时
（on-time 判据即 C ≤ due 且不被 H 截断），不影响完成率。

**第 2 步：设备占用也与 b 无关——因为 p > b 恒成立。**
全局 eligible 时长下界 min d = 1.2s（train 池 A/P 两族实测，见第 4 步诊断），故

```
p = α·d + β ≥ 0.75 × 1.2 + 0 = 0.9 > 0.2 = b_max下界
```

五种映射里 α 最小为 0.75、β 最小为 0，即使取下界中的下界也有 p ≥ 0.9。
因此 max(p, b) = p 对一切合法 b 成立：b 加大不会让设备更晚可用，
也不会让它更早可用——设备释放时刻恒为 s + p。

**第 3 步：空闲时间 idle = max(b − p, 0) = 0。**
由第 2 步 b − p < 0，idle 恒为零，与 b 无关。 Larger b 不带来任何"缓冲收益"。

**第 4 步：b 的唯一作用是掏钱。**
费用式中 b 只进预留费 0.1·b。b 越大，费用严格单调上升，其余一切指标不变。
故 b = 0.2 弱占优（weakly dominant）：所有指标不劣，费用严格更优。

**第 5 步：可行性不反噬。**
execute 的合法性要求 s + b ≤ H。取 b = 0.2 是给所有动作放了最宽的可行域；
任何 b = 0.2 可行的问题实例，b 更大反而可能撞 H 线被判 INVALID。
大 b 没有防御价值——设备是独占串行的，不存在"提前占位防别人抢"的对象。

## 4. 反方预设的反驳（写进论文堵审稿）

- **"大 b 能在超时失控时兜底？"** overrun = max(min(p, H−s) − b, 0) 里 b 确实削减
  overrun 读数，但那是把超时挪进"未完成"而不是消除——作业仍没完成，
  准时率照样受损，还多付了预留费。用 b 买"读数好看"是自欺。
- **"大 b 让设备提前占位？"** 设备可用时刻 = s + max(p, b)，b 只出现在 max 的
  败侧（p > b 恒成立），任何 b 都只会让可用时刻不变或更晚，绝不会更早。
- **"那 Q2 前缀信息能不能帮 b 调优？"** 不能。第 4 步 Q2 已证前缀对 d 的预测
  R² 为负（GBM 最优 −0.481），没有任何信号能区分"这单该多预留"；
  即使强行分位数预留（第 8 步对照扫描会算这笔账），也只是用真金白银的费用
  去换 overrun 读数，与准时率目标函数背道而驰。
